# Goal: Implement Deterministic Source Intelligence Layer

## Objective

Implement **only the new deterministic source-processing architecture** for Reforge.

The purpose is to solve large-file context saturation and Lost-in-the-Middle behavior before source is given to extraction sub-agents.

Do NOT implement, modify, or depend on the separate architectural work related to:

- ownership reconciliation
- semantic review
- scoped repair
- review severity
- Explorer projection
- proposal salvage
- source ledgers
- quality-gap remediation
- other senior-architect changes

This task is limited to the deterministic source layer and its integration with Reforge extraction agents.

---

# Problem

Current large-file behavior is effectively:

```text
Large Legacy File
      ↓
Read huge amount of source
      ↓
Context becomes saturated
      ↓
Sub-agent remembers source
      ↓
Extraction starts later
      ↓
Middle information is lost
```

Example stress case:

```text
Track.vb
~37,408 lines
~566 members
some very large methods
```

The architecture must prevent a sub-agent from using the entire large file as working memory.

# Core Principle

The deterministic layer decides:

```text
WHERE is the code?
WHERE does a method begin/end?
WHAT belongs together?
HOW large should one extraction task be?
WHAT exact source should a sub-agent receive?
```

The LLM decides:

```text
WHAT does the code mean?
WHAT business rule exists?
WHAT workflow exists?
WHAT requirement exists?
```

Never allow an LLM to decide source segmentation boundaries.

# Agent 3 — Segment Planner

## Responsibility

Convert structural units into bounded extraction segments.

Primary policy:

```text
Small file
   ↓
KEEP WHOLE


Large file
   ↓
Structural map
   ↓
Complete methods
   ↓
Pack adjacent methods
   ↓
Bounded segments
```

Example:

```text
Method A   120 lines
Method B   180 lines
Method C    90 lines

        ↓

SEG-001
A + B + C
```

Do not use:

```text
every 800 lines → split
```

as the primary strategy.

Preserve method integrity whenever possible.

---

# Agent 4 — Budget + Oversized Method Strategy

## Responsibility

Control segment size.

Use:

```text
PRIMARY
Token budget

SECONDARY
Line budget
```

Do not make line count alone the architecture.

Example:

```text
Methods A+B+C
     ↓
estimated tokens
     ↓
fits budget?
   /        \
 YES         NO
  │           │
pack       close segment
```

## Oversized Method

Some legacy methods may individually exceed the allowed budget.

Example:

```text
TrackTrainIDOn()
1,253 lines
```

For these:

```text
Oversized Method
       ↓
Control-Structure Scan
       ↓
safe top-level boundaries
       ↓
subsegments
```

Recognize:

```text
If / End If

Select Case / End Select

Try / Catch / Finally / End Try

For / Next

While / End While

Using / End Using

With / End With
```

Only split at safe structural boundaries.

# Agent 5 — Manifest + Coverage Validator

## Responsibility

Create deterministic source-segment metadata.

Example:

```json
{
  "file": "Track.vb",
  "file_hash": "...",
  "segments": [
    {
      "segment_id": "track-001",
      "start_line": 1,
      "end_line": 715,
      "strategy": "member-pack",
      "members": [
        "Initialize",
        "LoadTrack",
        "ValidateTrack"
      ]
    }
  ]
}
```

Validate:

```text
✓ beginning of source covered
✓ end of source covered

✓ no accidental gaps

✓ overlaps explicitly recorded

✓ every method assigned

✓ non-method source accounted for

✓ stable segment IDs

✓ source ordering preserved
```

Mandatory invariant:

```text
Source line 1
      ↓
      ↓
      ↓
Final source line

NO SILENT GAP
```

# Critical Extraction Rule

For large files:

> A sub-agent must not depend on previously accumulated whole-file context as the primary source for extraction.

The expected cycle is:

```text
READ
 ↓
UNDERSTAND
 ↓
EXTRACT
 ↓
WRITE
 ↓
MOVE TO NEXT SOURCE UNIT
```

 /          \

# Success Criteria

The architecture succeeds when:

```text
✓ Same source + config gives same segments

✓ Full source coverage

✓ No silent line gaps

✓ Methods remain intact when possible

✓ Oversized methods are safely subdivided

✓ Sub-agents operate on bounded source

✓ Extraction happens close to source reading

✓ One failed segment does not require
  rereading the entire huge source file

✓ Signal.vb middle coverage improves

✓ Track.vb can be processed without
  building one enormous model context
```
