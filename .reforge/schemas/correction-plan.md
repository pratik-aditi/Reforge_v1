# Correction Plan Schema

> Defines the structure for the correction plan (`correction-plan.xml`)

## Overview

The correction plan schema captures actionable corrections generated by `/reforge.audit`. Each correction item identifies a coverage gap or stale reference and recommends a specific reforge command to resolve it. The `/reforge.fix` command reads and updates this file during execution.

## Root Element

```xml
<correction-plan project-id="my-app" version="1.0.0"
                 generated="2024-01-15T14:00:00Z"
                 source-audit="reforge_output/my-app/audit/audit-report.xml"
                 total-items="15" completed-items="0">
  <correction>...</correction>
</correction-plan>
```

### Attributes

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `project-id` | string | Yes | Reference to analyzed project |
| `version` | string | Yes | Schema version |
| `generated` | dateTime | Yes | Plan creation timestamp |
| `source-audit` | string | Yes | Path to the audit report that generated this plan |
| `total-items` | integer | Yes | Total correction items in the plan |
| `completed-items` | integer | Yes | Items successfully fixed (updated by /reforge.fix) |

## Elements

### `<correction>`

Individual correction item with full context for execution.

```xml
<correction id="COR-001" priority="1" type="stale" category="extraction"
            extraction-type="business-rules" status="pending"
            action="/reforge.reanalyze src/old/LegacyPricing.java">
  <description>Business rule BR-045 references src/old/LegacyPricing.java which no longer exists. Re-analyze to update or remove the reference.</description>
  <affected-files>
    <file>src/old/LegacyPricing.java</file>
  </affected-files>
  <evidence>{Human-readable evidence supporting the correction — optional, present for accuracy/consistency corrections}</evidence>
</correction>
```

#### Attributes

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | Unique correction identifier (COR-001, COR-002, ...) |
| `priority` | integer | Yes | Execution order (1 = highest priority) |
| `type` | CorrectionType | Yes | Classification of the issue |
| `category` | CategoryType | Yes | Which layer needs fixing |
| `extraction-type` | string | No | Affected extraction type (when category is "extraction") |
| `status` | StatusType | Yes | Current execution status |
| `action` | string | Yes | Recommended reforge command to execute |
| `source-audit-type` | string | No | Which audit generated this correction: `coverage`, `accuracy`, or `consistency`. Present when generated by accuracy or consistency audits, or by the full audit merge. |
| `severity` | enum | No | Severity of the issue: `critical`, `high`, `medium`, or `low`. Present for accuracy and consistency corrections. |
| `completed-at` | dateTime | No | Timestamp when correction was completed |

#### CorrectionType Values

| Value | Description |
|-------|-------------|
| `gap` | File has no extraction coverage — needs extraction |
| `stale` | Extraction references a file that is missing or modified |
| `fabricated` | Extraction item has no evidence in the source codebase |
| `inaccurate` | Extraction item exists in source but with wrong value or context |
| `inconsistent` | Stated metadata count does not match actual element count |
| `broken-ref` | Cross-reference target (file or ID) does not resolve |
| `arithmetic` | Arithmetic total or distribution sum is incorrect |
| `duplicate-id` | Same element ID appears in multiple locations |
| `metric-mismatch` | Document value contradicts metrics registry |
| `unregistered-metric` | Document contains numeric claim not tracked by metrics registry |

#### CategoryType Values

| Value | Description | Priority Order |
|-------|-------------|---------------|
| `analysis` | Analysis inventory needs updating | 1st (highest) |
| `extraction` | Extraction needs to be (re-)performed | 2nd |
| `metadata` | Extraction metadata (counts, distributions) needs correcting | 3rd |
| `cross-document` | Cross-document discrepancy needs resolution | 4th |
| `metrics-consistency` | Metrics registry discrepancy needs resolution | 5th |
| `generation` | Generated output needs regeneration | 6th (lowest) |

#### StatusType Values

| Value | Description |
|-------|-------------|
| `pending` | Not yet executed |
| `in-progress` | Currently being executed by /reforge.fix |
| `completed` | Successfully fixed and verified |
| `failed` | Execution attempted but did not resolve the issue |
| `skipped` | User chose to skip in interactive mode |

### `<description>`

Human-readable description of what needs fixing and why.

### `<affected-files>`

List of file paths involved in this correction.

```xml
<affected-files>
  <file>src/service/PaymentService.java</file>
  <file>src/model/Payment.java</file>
</affected-files>
```

### `<evidence>`

Optional human-readable evidence supporting the correction. Present for accuracy and consistency audit corrections. Describes the specific checks that failed or the verification results that led to this correction.

```xml
<evidence>No word-boundary match for 'IVSA' found across 864 source files (0 matches). Expansion 'Inactive Vehicle Self-Assessment' not found near any occurrence.</evidence>
```

---

## Priority Assignment Rules

Corrections are prioritized by category (upstream before downstream):

1. **Analysis corrections** (priority 1-N): Fix the inventory first
2. **Extraction corrections** (priority N+1-M): Fix extractions after analysis is current
3. **Metadata corrections** (priority M+1-O): Fix extraction metadata (counts, distributions)
4. **Cross-document corrections** (priority O+1-P): Resolve cross-document discrepancies
5. **Metrics-consistency corrections** (priority P+1-Q): Fix numeric discrepancies against metrics registry
6. **Generation corrections** (priority Q+1-R): Regenerate after extractions are fixed

Within each category, corrections are ordered by:
- Severity: critical → high → medium → low (when severity is present)
- Stale references before gaps (fix broken things before adding new ones)
- Fabricated items before inaccurate items (remove hallucinations before fixing errors)
- metric-mismatch before unregistered-metric (fix known discrepancies before triaging new ones)
- Files with more components/lines first (higher-value files)

---

## Storage Location

Output path: `reforge_output/<project-name>/audit/correction-plan.xml`

---

## Lifecycle

```
1. /reforge.audit creates correction-plan.xml with all items status="pending"
2. User reviews plan
3. /reforge.fix reads plan, executes items in priority order
4. After each correction: status updated to "completed" or "failed"
5. completed-items count incremented on root element
6. Checkpoint saved to .reforge/memory/checkpoints/fix-checkpoint.xml
7. User may re-run /reforge.audit to generate updated plan
```

## Examples

### Plan with Mixed Corrections

```xml
<correction-plan project-id="legacy-ecommerce" version="1.0.0"
                 generated="2024-01-15T14:00:00Z"
                 source-audit="reforge_output/legacy-ecommerce/audit/audit-report.xml"
                 total-items="4" completed-items="0">

  <correction id="COR-001" priority="1" type="stale" category="extraction"
              extraction-type="business-rules" status="pending"
              action="/reforge.reanalyze src/old/LegacyPricing.java --force">
    <description>BR-045 references src/old/LegacyPricing.java which has been deleted. Re-analyze to remove stale extraction.</description>
    <affected-files>
      <file>src/old/LegacyPricing.java</file>
    </affected-files>
  </correction>

  <correction id="COR-002" priority="2" type="stale" category="extraction"
              extraction-type="workflows" status="pending"
              action="/reforge.reanalyze src/service/OrderService.java">
    <description>WF-012 references src/service/OrderService.java which has been modified since extraction. Re-analyze to update workflow.</description>
    <affected-files>
      <file>src/service/OrderService.java</file>
    </affected-files>
  </correction>

  <correction id="COR-003" priority="3" type="gap" category="extraction"
              extraction-type="business-rules" status="pending"
              action="/reforge.extract business-rules --files src/service/PaymentService.java">
    <description>src/service/PaymentService.java has no business rule extractions. Extract business rules from this file.</description>
    <affected-files>
      <file>src/service/PaymentService.java</file>
    </affected-files>
  </correction>

  <correction id="COR-004" priority="4" type="gap" category="extraction"
              extraction-type="database" status="pending"
              action="/reforge.extract database --files src/repository/PaymentRepository.java">
    <description>src/repository/PaymentRepository.java has no database extractions. Extract database interactions from this file.</description>
    <affected-files>
      <file>src/repository/PaymentRepository.java</file>
    </affected-files>
  </correction>

</correction-plan>
```

### Plan with Accuracy Corrections (Fabricated Items)

```xml
<correction-plan project-id="TCOS-RUMO" version="1.0.0"
                 generated="2024-01-15T14:00:00Z"
                 source-audit="reforge_output/TCOS-RUMO/audit/accuracy-audit-report.xml"
                 total-items="3" completed-items="0">

  <correction id="COR-001" priority="1" type="fabricated" category="extraction"
              extraction-type="business-rules" status="pending"
              source-audit-type="accuracy" severity="critical"
              action="delete business-rules.xml ACR-015">
    <description>Acronym ACR-015 'IVSA' (Inactive Vehicle Self-Assessment) has no evidence in the source codebase. Delete from extraction XML.</description>
    <affected-files>
      <file>reforge_output/TCOS-RUMO/extractions/business-rules.xml</file>
    </affected-files>
    <evidence>No word-boundary match for 'IVSA' found across 864 source files (0 matches). Expansion 'Inactive Vehicle Self-Assessment' not found near any occurrence.</evidence>
  </correction>

  <correction id="COR-002" priority="2" type="inaccurate" category="extraction"
              extraction-type="ui-flows" status="pending"
              source-audit-type="accuracy" severity="high"
              action="/reforge.reanalyze src/views/DashboardView.vb">
    <description>UI flow UF-023 references line 145 of DashboardView.vb but the actual content at that line does not match the extracted snippet. Re-analyze to correct.</description>
    <affected-files>
      <file>src/views/DashboardView.vb</file>
    </affected-files>
    <evidence>Content-match check failed: extracted snippet 'btnSubmit.Enabled = False' not found at stated line 145. Nearest match at line 162.</evidence>
  </correction>

  <correction id="COR-003" priority="3" type="inconsistent" category="metadata"
              status="pending"
              source-audit-type="consistency" severity="medium"
              action="update-metadata business-rules.xml total-count">
    <description>business-rules.xml metadata states 900 business rules but actual element count is 981. Update metadata count.</description>
    <affected-files>
      <file>reforge_output/TCOS-RUMO/extractions/business-rules.xml</file>
    </affected-files>
    <evidence>Arithmetic check: metadata/total-count states 900, actual child element count is 981 (difference: +81).</evidence>
  </correction>

</correction-plan>
```

### Plan with Metrics Consistency Corrections

```xml
<correction-plan project-id="TCOS-RUMO" version="1.0.0"
                 generated="2024-01-15T14:00:00Z"
                 source-audit="reforge_output/TCOS-RUMO/audit/consistency-audit-report.xml"
                 total-items="3" completed-items="0">

  <correction id="COR-001" priority="1" type="metric-mismatch" category="metrics-consistency"
              status="pending"
              source-audit-type="consistency" severity="critical"
              action="/reforge.generate markdown --refresh-metrics">
    <description>documentation.md states 785 business rules but metrics registry value is 981 (MET-BR-COUNT). Regenerate documentation to use registry value.</description>
    <affected-files>
      <file>reforge_output/TCOS-RUMO/generated/documentation.md</file>
    </affected-files>
    <evidence>Metrics registry check: MET-BR-COUNT registry value 981, document value 785 at line 42. Exact mismatch (no qualifier present).</evidence>
  </correction>

  <correction id="COR-002" priority="2" type="metric-mismatch" category="metrics-consistency"
              status="pending"
              source-audit-type="consistency" severity="warning"
              action="/reforge.generate user-stories --refresh-metrics">
    <description>user-stories.md states "approximately 850 business rules" but metrics registry value is 981. Value is outside ±10% tolerance for approximate qualifier.</description>
    <affected-files>
      <file>reforge_output/TCOS-RUMO/generated/user-stories.md</file>
    </affected-files>
    <evidence>Metrics registry check: MET-BR-COUNT registry value 981, document value 850 with qualifier "approximately" at line 15. Tolerance ±10% allows 883-1079, value 850 is below range.</evidence>
  </correction>

  <correction id="COR-003" priority="3" type="unregistered-metric" category="metrics-consistency"
              status="pending"
              source-audit-type="consistency" severity="info"
              action="register-or-exclude documentation.md line 87">
    <description>documentation.md contains unregistered numeric claim "47 integration points" at line 87 not tracked by any registry metric. Register as new metric or add to exclusion list.</description>
    <affected-files>
      <file>reforge_output/TCOS-RUMO/generated/documentation.md</file>
    </affected-files>
    <evidence>Unregistered metric scan: numeric claim "47 integration points" found at documentation.md:87. No matching metric ID in registry. Not in exclusion list.</evidence>
  </correction>

</correction-plan>
```
