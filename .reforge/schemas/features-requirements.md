# Features & Requirements Schema

> Defines the structure for derived features and requirements (`features-requirements.xml`)

## Overview

The features-requirements schema captures features, functional requirements, and non-functional requirements derived from extraction analysis. Generated by `/reforge.generate features`.

## Root Element

```xml
<features-requirements project-id="my-app" version="1.0.0"
                       generated="2024-01-15T10:30:00Z">
  <features>...</features>
  <functional-requirements>...</functional-requirements>
  <non-functional-requirements>...</non-functional-requirements>
</features-requirements>
```

### Attributes

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `project-id` | string | Yes | Reference to analysis project |
| `version` | string | Yes | Schema version |
| `generated` | dateTime | Yes | Generation timestamp |

## Elements

### `<features>`

Container for all identified features.

```xml
<features count="8">
  <feature>...</feature>
</features>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `count` | integer | Yes | Total features identified |

### `<feature>`

Individual feature derived from extraction patterns.

```xml
<feature id="FT-001" name="Order Management" priority="high">
  <description>End-to-end order lifecycle management including creation, pricing, and fulfillment</description>
  <capabilities>
    <capability>Create new orders</capability>
    <capability>Apply discount rules</capability>
    <capability>Track order status</capability>
  </capabilities>
  <source-components>
    <component type="workflow" ref="WF-001"/>
    <component type="workflow" ref="WF-003"/>
    <component type="screen" ref="SCR-001"/>
    <component type="screen" ref="SCR-002"/>
  </source-components>
  <related-rules>
    <rule-ref id="BR-001"/>
    <rule-ref id="BR-002"/>
  </related-rules>
  <related-workflows>
    <workflow-ref id="WF-001"/>
  </related-workflows>
</feature>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | Feature ID (FT-XXX) |
| `name` | string | Yes | Descriptive feature name |
| `priority` | enum | Yes | `critical`, `high`, `medium`, `low` |

#### Child Elements

| Element | Required | Description |
|---------|----------|-------------|
| `<description>` | Yes | Feature description |
| `<capabilities>` | Yes | List of capabilities this feature provides |
| `<source-components>` | Yes | Extraction artifacts that define this feature |
| `<related-rules>` | No | Business rules associated with this feature |
| `<related-workflows>` | No | Workflows that implement this feature |

### `<functional-requirements>`

Container for functional requirements.

```xml
<functional-requirements count="25">
  <requirement>...</requirement>
</functional-requirements>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `count` | integer | Yes | Total functional requirements |

### `<requirement>` (functional)

Individual functional requirement derived from extractions.

```xml
<requirement id="FR-001" feature="FT-001" priority="high">
  <description>System shall apply volume discount when order total exceeds threshold</description>
  <acceptance-criteria>
    <criterion>Given an order with total > $100, when submitted, then 10% discount is applied</criterion>
    <criterion>Given an order with total <= $100, when submitted, then no discount is applied</criterion>
  </acceptance-criteria>
  <source-evidence>
    <evidence type="business-rule" ref="BR-001"/>
    <evidence type="workflow" ref="WF-001" step="2"/>
  </source-evidence>
</requirement>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | Requirement ID (FR-XXX) |
| `feature` | string | Yes | Parent feature ID |
| `priority` | enum | Yes | `critical`, `high`, `medium`, `low` |

#### Child Elements

| Element | Required | Description |
|---------|----------|-------------|
| `<description>` | Yes | Requirement description |
| `<acceptance-criteria>` | Yes | Testable acceptance criteria |
| `<source-evidence>` | Yes | Extraction references that support this requirement |

### `<non-functional-requirements>`

Container for non-functional requirements.

```xml
<non-functional-requirements count="10">
  <requirement>...</requirement>
</non-functional-requirements>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `count` | integer | Yes | Total non-functional requirements |

### `<requirement>` (non-functional)

Individual non-functional requirement derived from code patterns.

```xml
<requirement id="NFR-001" category="performance" priority="high">
  <description>Order submission response time must meet threshold</description>
  <metric>Response time</metric>
  <threshold>&lt;200ms for 95th percentile</threshold>
  <source-evidence>
    <evidence type="workflow" ref="WF-001"/>
    <evidence type="database-interaction" ref="DB-002"/>
  </source-evidence>
</requirement>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | Requirement ID (NFR-XXX) |
| `category` | enum | Yes | `performance`, `security`, `scalability`, `reliability`, `usability`, `maintainability` |
| `priority` | enum | Yes | `critical`, `high`, `medium`, `low` |

#### Child Elements

| Element | Required | Description |
|---------|----------|-------------|
| `<description>` | Yes | Requirement description |
| `<metric>` | Yes | Measurable metric |
| `<threshold>` | Yes | Target threshold value |
| `<source-evidence>` | Yes | Extraction references that support this requirement |

### `<evidence>`

Source evidence reference within a requirement.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `type` | string | Yes | Evidence type: `business-rule`, `workflow`, `ui-component`, `database-interaction` |
| `ref` | string | Yes | Artifact ID |
| `step` | string | No | Specific step within a workflow |

## Example

```xml
<?xml version="1.0" encoding="UTF-8"?>
<features-requirements project-id="legacy-ecommerce" version="1.0.0"
                       generated="2024-01-15T14:00:00Z">

  <features count="2">
    <feature id="FT-001" name="Order Management" priority="high">
      <description>End-to-end order lifecycle management</description>
      <capabilities>
        <capability>Create new orders</capability>
        <capability>Apply discount rules</capability>
        <capability>Track order status</capability>
      </capabilities>
      <source-components>
        <component type="workflow" ref="WF-001"/>
        <component type="screen" ref="SCR-001"/>
        <component type="screen" ref="SCR-002"/>
      </source-components>
      <related-rules>
        <rule-ref id="BR-001"/>
        <rule-ref id="BR-002"/>
      </related-rules>
      <related-workflows>
        <workflow-ref id="WF-001"/>
      </related-workflows>
    </feature>

    <feature id="FT-002" name="Customer Management" priority="medium">
      <description>Customer registration and profile management</description>
      <capabilities>
        <capability>Register new customers</capability>
        <capability>View customer details</capability>
      </capabilities>
      <source-components>
        <component type="workflow" ref="WF-005"/>
        <component type="screen" ref="SCR-005"/>
      </source-components>
      <related-rules>
        <rule-ref id="BR-010"/>
      </related-rules>
      <related-workflows>
        <workflow-ref id="WF-005"/>
      </related-workflows>
    </feature>
  </features>

  <functional-requirements count="3">
    <requirement id="FR-001" feature="FT-001" priority="high">
      <description>System shall apply volume discount when order total exceeds $100</description>
      <acceptance-criteria>
        <criterion>Given an order totaling > $100, when submitted, then 10% discount applied</criterion>
        <criterion>Given an order totaling <= $100, when submitted, then no discount applied</criterion>
      </acceptance-criteria>
      <source-evidence>
        <evidence type="business-rule" ref="BR-001"/>
        <evidence type="workflow" ref="WF-001" step="2"/>
      </source-evidence>
    </requirement>

    <requirement id="FR-002" feature="FT-001" priority="high">
      <description>System shall validate that orders contain at least one item</description>
      <acceptance-criteria>
        <criterion>Given an empty order, when submitted, then validation error is returned</criterion>
      </acceptance-criteria>
      <source-evidence>
        <evidence type="business-rule" ref="BR-002"/>
      </source-evidence>
    </requirement>

    <requirement id="FR-003" feature="FT-002" priority="medium">
      <description>System shall enforce unique email addresses for customers</description>
      <acceptance-criteria>
        <criterion>Given a duplicate email, when registering, then error is displayed</criterion>
      </acceptance-criteria>
      <source-evidence>
        <evidence type="business-rule" ref="BR-010"/>
      </source-evidence>
    </requirement>
  </functional-requirements>

  <non-functional-requirements count="2">
    <requirement id="NFR-001" category="performance" priority="high">
      <description>Order submission must complete within acceptable time</description>
      <metric>Response time</metric>
      <threshold>&lt;200ms for 95th percentile</threshold>
      <source-evidence>
        <evidence type="workflow" ref="WF-001"/>
        <evidence type="database-interaction" ref="DB-002"/>
      </source-evidence>
    </requirement>

    <requirement id="NFR-002" category="security" priority="critical">
      <description>Order operations require authenticated user session</description>
      <metric>Authentication coverage</metric>
      <threshold>100% of order endpoints</threshold>
      <source-evidence>
        <evidence type="business-rule" ref="BR-015"/>
        <evidence type="workflow" ref="WF-001"/>
      </source-evidence>
    </requirement>
  </non-functional-requirements>

</features-requirements>
```

## Schema Notes

This is a derived schema for features and requirements output. No formal XSD contract exists as features-requirements are generated from extraction analysis. This markdown documentation serves as the authoritative schema definition.
