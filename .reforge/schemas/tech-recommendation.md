# Tech Recommendation Schema

> Defines the structure for technology stack recommendations (`tech-recommendation.xml`)

## Overview

The tech-recommendation schema captures technology stack recommendations generated by `/reforge.recommend`. It evaluates the current architecture and non-functional requirements to propose modernization technologies with scored rationale and migration effort assessments.

## Common Elements

This schema extends the [Common Extraction Schema](./common-schema.md), which defines shared structural elements used across all extraction types:

- **Root attributes**: `project-id`, `version`, `schema-version`, `generated`, `xmlns`
- **Metadata container**: `<metadata>` with `<total-count>`, `<confidence-distribution>`, `<extraction-timestamp>`
- **Confidence vocabulary**: `high`, `medium`, `low` enumeration
- **ID patterns**: `REC-{CATEGORY}-{SEQUENCE}` (recommendations)

See `common-schema.md` for complete definitions. Elements defined there MUST NOT be redefined in this schema.

## Root Element

```xml
<tech-recommendation xmlns="http://reforge.dev/schema/extraction"
                     project-id="my-app" version="1.0.0"
                     schema-version="1.0.0"
                     generated="2024-01-15T10:30:00Z">
  <metadata>...</metadata>
  <evaluation-criteria>...</evaluation-criteria>
  <recommendations>...</recommendations>
</tech-recommendation>
```

### Attributes

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `xmlns` | URI | Yes | Must be `http://reforge.dev/schema/extraction` |
| `project-id` | string | Yes | Reference to analysis project |
| `version` | string | Yes | Recommendation version (semver) |
| `schema-version` | string | Yes | Common schema version (initial: `1.0.0`) |
| `generated` | dateTime | Yes | Generation timestamp (ISO-8601) |

> Root attributes and `<metadata>` are defined by the [Common Extraction Schema](./common-schema.md). The `<metadata>` element is required as the first child of the root element. The metadata `<total-count>` equals the count of recommendation items.

## Elements

### `<evaluation-criteria>`

Documents the criteria used to score and rank recommendations.

```xml
<evaluation-criteria>
  <criterion name="maturity" weight="0.20" description="Community adoption and ecosystem maturity"/>
  <criterion name="migration-cost" weight="0.25" description="Effort and risk of migration from current stack"/>
  <criterion name="performance" weight="0.20" description="Runtime performance characteristics"/>
  <criterion name="team-skills" weight="0.15" description="Alignment with existing team expertise"/>
  <criterion name="ecosystem" weight="0.10" description="Tooling, libraries, and community support"/>
  <criterion name="long-term-viability" weight="0.10" description="Long-term maintenance and vendor stability"/>
</evaluation-criteria>
```

### `<criterion>`

Individual evaluation criterion used for scoring recommendations.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | Criterion identifier |
| `weight` | decimal | Yes | Scoring weight (0.0-1.0, all weights should sum to 1.0) |
| `description` | string | Yes | Human-readable description of the criterion |

### `<recommendations>`

Container for all technology recommendations.

```xml
<recommendations count="5">
  <recommendation>...</recommendation>
</recommendations>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `count` | integer | Yes | Number of recommendation items |

### `<recommendation>`

Individual technology recommendation with rationale and migration assessment.

```xml
<recommendation id="REC-LANG-001" category="language" priority="high" score="0.85">
  <current>Java 8 with Spring Boot 1.x</current>
  <proposed>Java 17 with Spring Boot 3.x</proposed>
  <rationale>Java 17 provides records, sealed classes, and pattern matching that reduce boilerplate. Spring Boot 3.x offers native compilation support and improved observability.</rationale>
  <migration-effort level="medium" estimated-weeks="12">
    Requires updating build tooling, replacing deprecated APIs, and validating compatibility with existing libraries.
  </migration-effort>
  <risk-assessment level="low">
    Well-documented migration path. Spring Boot 3.x migration guide covers most breaking changes.
  </risk-assessment>
  <alternatives>
    <alternative name="Kotlin with Spring Boot 3.x" reason="Higher learning curve for existing Java team"/>
    <alternative name="Java 21 with Quarkus" reason="Less mature ecosystem for enterprise patterns"/>
  </alternatives>
  <nfr-alignment>
    <nfr-ref id="NFR-PERF-001">Addresses response time requirements via native compilation</nfr-ref>
    <nfr-ref id="NFR-MAINT-002">Improves maintainability through modern language features</nfr-ref>
  </nfr-alignment>
</recommendation>
```

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | Unique identifier: `REC-{CATEGORY}-{SEQUENCE}` |
| `category` | string | Yes | Technology category (see categories below) |
| `priority` | string | Yes | Recommendation priority: `critical`, `high`, `medium`, `low` |
| `score` | decimal | Yes | Weighted score (0.0-1.0) based on evaluation criteria |

### `<current>`

Description of the current technology or approach being used in the legacy system.

### `<proposed>`

The recommended replacement technology or upgrade path.

### `<rationale>`

Explanation of why this technology is recommended, referencing specific evaluation criteria and project requirements.

### `<migration-effort>`

Assessment of the effort required to adopt the proposed technology.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `level` | string | Yes | Effort level: `low`, `medium`, `high`, `very-high` |
| `estimated-weeks` | integer | No | Rough estimate of calendar weeks for migration |

The element text contains a description of what the migration entails.

### `<risk-assessment>`

Assessment of risks associated with adopting the proposed technology.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `level` | string | Yes | Risk level: `low`, `medium`, `high`, `critical` |

The element text contains a description of specific risks and mitigations.

### `<alternatives>`

Container for alternative technologies that were considered but not recommended as the primary choice.

### `<alternative>`

An alternative technology that was evaluated.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | string | Yes | Name of the alternative technology |
| `reason` | string | Yes | Reason it was not selected as the primary recommendation |

### `<nfr-alignment>`

Maps the recommendation to non-functional requirements it addresses.

### `<nfr-ref>`

Reference to a non-functional requirement satisfied by this recommendation.

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | string | Yes | ID of the non-functional requirement (e.g., `NFR-PERF-001`) |

The element text describes how the recommendation addresses the requirement.

## Recommendation Categories

| Category | Description | Examples |
|----------|-------------|----------|
| `language` | Programming language | Java 17, Kotlin, TypeScript |
| `framework` | Application framework | Spring Boot 3.x, .NET 8, Next.js |
| `database` | Data storage | PostgreSQL 16, MongoDB 7, Redis |
| `cloud` | Cloud platform and services | AWS, Azure, GCP managed services |
| `messaging` | Message brokers and event systems | Kafka, RabbitMQ, Azure Service Bus |
| `frontend` | Frontend framework | React 18, Angular 17, Vue 3 |
| `devops` | CI/CD and infrastructure | GitHub Actions, Terraform, Docker |
| `observability` | Monitoring and logging | OpenTelemetry, Grafana, Datadog |

```xml
<?xml version="1.0" encoding="UTF-8"?>
<tech-recommendation xmlns="http://reforge.dev/schema/extraction"
                     project-id="ecommerce-legacy" version="1.0.0"
                     schema-version="1.0.0"
                     generated="2024-01-15T10:30:00Z">

  <metadata>
    <total-count>2</total-count>
    <confidence-distribution>
      <high>1</high>
      <medium>1</medium>
      <low>0</low>
    </confidence-distribution>
    <extraction-timestamp>2024-01-15T10:30:00Z</extraction-timestamp>
  </metadata>

  <evaluation-criteria>
    <criterion name="maturity" weight="0.20" description="Community adoption and ecosystem maturity"/>
    <criterion name="migration-cost" weight="0.25" description="Effort and risk of migration from current stack"/>
    <criterion name="performance" weight="0.20" description="Runtime performance characteristics"/>
    <criterion name="team-skills" weight="0.15" description="Alignment with existing team expertise"/>
    <criterion name="ecosystem" weight="0.10" description="Tooling, libraries, and community support"/>
    <criterion name="long-term-viability" weight="0.10" description="Long-term maintenance and vendor stability"/>
  </evaluation-criteria>

  <recommendations count="2">
    <recommendation id="REC-LANG-001" category="language" priority="high" score="0.85">
      <current>Java 8 with Spring Boot 1.x</current>
      <proposed>Java 17 with Spring Boot 3.x</proposed>
      <rationale>Java 17 provides records, sealed classes, and pattern matching that reduce boilerplate. Spring Boot 3.x offers native compilation support and improved observability.</rationale>
      <migration-effort level="medium" estimated-weeks="12">
        Requires updating build tooling, replacing deprecated APIs, and validating compatibility with existing libraries.
      </migration-effort>
      <risk-assessment level="low">
        Well-documented migration path. Spring Boot 3.x migration guide covers most breaking changes.
      </risk-assessment>
      <alternatives>
        <alternative name="Kotlin with Spring Boot 3.x" reason="Higher learning curve for existing Java team"/>
        <alternative name="Java 21 with Quarkus" reason="Less mature ecosystem for enterprise patterns"/>
      </alternatives>
      <nfr-alignment>
        <nfr-ref id="NFR-PERF-001">Addresses response time requirements via native compilation</nfr-ref>
      </nfr-alignment>
    </recommendation>

    <recommendation id="REC-DB-001" category="database" priority="medium" score="0.72">
      <current>Oracle 11g with manual SQL</current>
      <proposed>PostgreSQL 16 with JPA/Hibernate</proposed>
      <rationale>PostgreSQL provides equivalent enterprise features with no licensing cost. JPA abstraction enables database-agnostic code.</rationale>
      <migration-effort level="high" estimated-weeks="20">
        Requires SQL dialect conversion, stored procedure migration, and data migration tooling.
      </migration-effort>
      <risk-assessment level="medium">
        Oracle-specific SQL features (CONNECT BY, MODEL clause) require manual rewrite. Data migration needs thorough validation.
      </risk-assessment>
      <alternatives>
        <alternative name="MySQL 8" reason="Less feature parity with Oracle for complex queries"/>
        <alternative name="Azure SQL" reason="Vendor lock-in concern"/>
      </alternatives>
      <nfr-alignment>
        <nfr-ref id="NFR-COST-001">Eliminates Oracle licensing costs</nfr-ref>
        <nfr-ref id="NFR-MAINT-001">Simplifies database administration</nfr-ref>
      </nfr-alignment>
    </recommendation>
  </recommendations>

</tech-recommendation>
```
