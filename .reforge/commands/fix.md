# /reforge.fix

> Execute corrections from the audit correction plan

## Command Syntax

```
/reforge.fix [--type <type>] [--items <ids>] [--interactive] [--resume] [--json]
```

### Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| `--type <type>` | No | Limit to corrections for a specific extraction type (e.g., `business-rules`, `database`) |
| `--items <ids>` | No | Execute only specific correction IDs (comma-separated, e.g., `COR-001,COR-003`) |
| `--interactive` | No | Prompt for confirmation before each correction |
| `--resume` | No | Resume from last checkpoint after interruption |
| `--json` | No | Output fix results as JSON for tooling integration |

## Overview

This command reads the correction plan generated by `/reforge.audit` and executes corrections in dependency order:

1. **Analysis corrections** — Fix the inventory first (re-analyze stale files)
2. **Extraction corrections** — Fix extractions after analysis is current (re-extract or fill gaps)
3. **Generation corrections** — Regenerate after extractions are fixed

Each correction dispatches to the appropriate reforge command (`/reforge.reanalyze`, `/reforge.extract`, `/reforge.generate`).

## Prerequisites

- Completed audit with correction plan (`$AUDIT_DIR/correction-plan.xml` must exist)
- Correction plan must have pending items

---

## Workflow

### Step 0: Check Prerequisites

Run the prerequisites script to validate state and resolve paths:

```bash
reforge-scripts check-prerequisites --json --require-audit
```

This returns JSON with resolved variables:
```json
{"PROJECT_NAME":"...","REPO_ROOT":"...","PROJECT_OUTPUT_DIR":"...","CONFIG":"...","ANALYSIS_STATUS":"completed","AVAILABLE_EXTRACTIONS":[...],"CHECKPOINT":null,"CLARIFICATIONS_DIR":"..."}
```

Use `$PROJECT_OUTPUT_DIR`, `$PROJECT_NAME` throughout subsequent steps.

Assign subdirectory variables:
```
$AUDIT_DIR = $PROJECT_OUTPUT_DIR/audit
$EXTRACTIONS_DIR = $PROJECT_OUTPUT_DIR/extractions
$ANALYSIS_DIR = $PROJECT_OUTPUT_DIR/analysis
```

Read the correction plan:
```
$CORRECTION_PLAN = $AUDIT_DIR/correction-plan.xml
```

Validate the plan exists and has pending items:
- If no pending items remain: Report "All corrections already completed" and exit
- If plan is empty: Report error and suggest running `/reforge.audit`

### Step 0.5: Load Project Context

If `.reforge/memory/project-context.md` exists, read it now. Use its contents as
supplemental guidance throughout this command's execution:
- **Technology Stack**: Informs language/framework detection and pattern recognition
- **Domain Knowledge**: Provides business context for naming and categorization
- **Analysis Guidelines**: Directs focus and exclusions beyond config.json
- **Custom Rules**: Additional rules to follow alongside the constitution

### Step 1: Check for Resume State

If `--resume` flag is provided:

1. **Read checkpoint file**: `.reforge/memory/checkpoints/fix-checkpoint.xml`
2. **Extract resume state**:
   - `last-completed-id`: The last correction that completed successfully
   - `completed-count`: Number already done
   - `failed-items`: IDs that previously failed (skip these unless re-attempted)
3. **Filter plan**: Remove already-completed items from the execution queue
4. **Report resume state**:
   ```
   Resuming fix execution...
   Previously completed: [N] corrections
   Remaining: [M] corrections
   [If failed items:] Previously failed: [IDs] (will retry)
   ```

If `--resume` flag is provided but no checkpoint exists:
```
No checkpoint found. Starting fresh execution.
```

### Step 2: Sort and Filter Corrections

**Apply filters** (if specified):

1. **`--type` filter**: Keep only corrections where `extraction-type` matches the specified type
2. **`--items` filter**: Keep only corrections whose `id` matches one of the comma-separated IDs

**Sort remaining corrections by dependency order**:

1. Group by `category`:
   - `analysis` first (priority group 1)
   - `extraction` second (priority group 2)
   - `generation` third (priority group 3)

2. Within each category, sort by `priority` number (ascending — lower number = higher priority)

**Report execution plan**:
```
Execution plan:
  [N] corrections to execute
  Order: [analysis: X] → [extraction: Y] → [generation: Z]
```

### Step 3: Execute Corrections Loop

For each pending correction item in sorted order:

#### 3a. Pre-execution

1. **Update status** in `correction-plan.xml`: Set `status="in-progress"`
2. **Display current correction**:
   ```
   [X/N] Executing COR-001 (stale/extraction/business-rules)
         Action: /reforge.reanalyze src/old/LegacyPricing.java
         Files: src/old/LegacyPricing.java
   ```

#### 3b. Interactive Mode Check

If `--interactive` flag is set, display correction details and prompt:

```
--- Correction COR-001 ---
Type: stale reference
Category: extraction (business-rules)
Description: BR-045 references src/old/LegacyPricing.java which no longer exists.
Action: /reforge.reanalyze src/old/LegacyPricing.java
Affected files:
  - src/old/LegacyPricing.java

Proceed? (yes/skip/abort)
```

- **yes**: Execute this correction
- **skip**: Mark as `status="skipped"` and continue to next
- **abort**: Stop execution, save checkpoint, exit

#### 3c. Execute Action

Dispatch to the appropriate reforge command based on the `action` field:

**For `/reforge.reanalyze <path>` actions:**
- Execute the reanalyze workflow on the specified file path
- This updates analysis.xml and affected extraction entries

**For `/reforge.extract <type> --files <path>` actions:**
- Execute the extract workflow for the specified type and file
- This creates new extraction entries for the uncovered file

**For `/reforge.generate <artifact>` actions:**
- Execute the generate workflow for the specified artifact type
- This regenerates downstream documentation

**Execution approach**: Run the action as described in the corresponding command template. The AI agent should follow the workflow steps of the dispatched command inline (not as a separate slash command invocation), applying the relevant steps to the specified files.

#### 3d. Save Checkpoint

After each successful correction:

Write checkpoint to `.reforge/memory/checkpoints/fix-checkpoint.xml`:
```xml
<fix-checkpoint>
  <plan-path>$AUDIT_DIR/correction-plan.xml</plan-path>
  <started-at>[timestamp]</started-at>
  <last-completed-id>[COR-XXX]</last-completed-id>
  <total-items>[N]</total-items>
  <completed-count>[M]</completed-count>
  <failed-items>
    <item id="COR-YYY"/>
  </failed-items>
</fix-checkpoint>
```

### Step 4: Spot-Check Verification

After each correction completes, verify the fix was effective:

**For gap corrections** (type="gap"):
- Re-read the relevant extraction XML file(s)
- Check if the affected file path now appears in `<source file="...">` attributes
- If found: Correction verified

**For stale corrections** (type="stale"):
- Re-read the relevant extraction XML file(s)
- Check if the stale reference has been updated or removed
- Verify the referenced file path is now valid (exists on disk)
- If resolved: Correction verified

**Update correction status**:
- If verification passes: `status="completed"`, add `completed-at="[timestamp]"`
- If verification fails: `status="failed"`
  ```
  ⚠ Correction COR-001 executed but verification failed.
    Expected: src/old/LegacyPricing.java to have extraction coverage
    Actual: No extraction reference found after re-analysis
    Continuing with remaining corrections...
  ```

### Step 5: Update Plan and Checkpoint

After all corrections have been attempted:

1. **Update `correction-plan.xml`**:
   - Update `completed-items` count on root element
   - All item statuses should now be "completed", "failed", or "skipped"

2. **Write final checkpoint**:
   - Update `.reforge/memory/checkpoints/fix-checkpoint.xml` with final state

3. **Clean up checkpoint** (if all items completed successfully):
   - Remove checkpoint file (no resume needed)

### Step 6: Report Results

Display execution summary:

```
=== Fix Execution Complete ===

Results:
  Total corrections: [N]
  Completed: [X] ✓
  Failed: [Y] ✗
  Skipped: [Z] ○
  [If resumed:] Previously completed: [P]

[If failures:]
Failed corrections:
  COR-004: /reforge.extract database --files src/repository/PaymentRepository.java
    Reason: File encoding error prevented extraction
  ...

[If skipped:]
Skipped corrections:
  COR-007: Skipped by user (interactive mode)
  ...

--- Next Steps ---
[If all completed:]
→ Run /reforge.audit to verify improved coverage
[If failures:]
→ Review failed corrections and fix underlying issues
→ Run /reforge.fix --resume to retry failed items
[If skipped:]
→ Run /reforge.fix --items [skipped-ids] to execute skipped corrections
```

## Error Handling

### Missing Correction Plan

If correction-plan.xml does not exist (caught by prerequisites script):

```
Error: Correction plan not found. Run /reforge.audit first.
  Expected: $AUDIT_DIR/correction-plan.xml

The fix command requires a correction plan generated by /reforge.audit.
Run /reforge.audit to identify coverage gaps and generate a correction plan.
```

### Correction Execution Failures

When a correction action fails during execution:

1. **Log the failure**: Record error details
2. **Update status**: Set `status="failed"` in correction-plan.xml
3. **Save checkpoint**: Preserve progress for resume
4. **Continue execution**: Proceed to next correction (do not abort)

```
⚠ Correction COR-004 failed:
  Action: /reforge.extract database --files src/repository/PaymentRepository.java
  Error: File encoding error prevented extraction
  Saving progress and continuing...
```

### Checkpoint Corruption

If checkpoint file exists but is malformed:

```
Warning: Fix checkpoint is corrupted or unreadable.
  Path: .reforge/memory/checkpoints/fix-checkpoint.xml
  Starting fresh execution (all pending items).
```

### No Pending Items

If all corrections in the plan are already completed/failed/skipped:

```
All corrections have been processed.
  Completed: [X]
  Failed: [Y]
  Skipped: [Z]

No pending corrections to execute.
Run /reforge.audit to generate a fresh correction plan if needed.
```
