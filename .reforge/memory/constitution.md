# Reforge Constitution

## Core Principles

### I. LLM-First Architecture

Reforge is an **LLM-driven framework** — the AI agent (Claude Code, GitHub Copilot, or equivalent) performs all analysis, extraction, and generation using its native capabilities. There is NO compiled code, NO runtime dependencies, NO external parsers.

**Non-negotiable rules:**
- All analysis MUST be performed by the LLM using Read, Glob, Grep, and similar agent tools
- All output MUST be generated by the LLM using Write tool
- NO Tree-sitter, NO AST parsers, NO language-specific tooling in the framework itself
- The framework consists entirely of prompt templates, schemas, and configuration files

**Rationale:** LLMs can understand code semantically across any language without custom parsers. This eliminates dependency complexity and makes the framework instantly usable in any AI-assisted environment.

### II. Prompt Template Commands

Every Reforge capability is exposed as a **slash command** backed by a markdown prompt template. Commands guide the LLM through structured workflows.

**Non-negotiable rules:**
- Commands MUST be defined as markdown files in `.reforge/commands/`
- Command names MUST follow pattern: `/reforge.<action>` (e.g., `/reforge.analyze`, `/reforge.extract`)
- Each command MUST be self-contained with clear inputs, steps, and outputs
- Commands MUST NOT require external tool execution (beyond LLM-native tools)

**Rationale:** Prompt templates are portable across AI agents, version-controllable, and require no installation beyond copying files.

### III. Structured Output (XML/Markdown)

All extraction and analysis results MUST be stored in **structured, human-readable formats** that LLMs can easily parse and generate.

**Non-negotiable rules:**
- Extracted knowledge MUST be stored as XML with defined schemas OR structured markdown
- Schemas MUST be documented in `.reforge/schemas/`
- Output MUST include source references (file path, line numbers) for traceability
- Output MUST be deterministic given the same input and prompts

**Rationale:** Structured output enables downstream processing, validation, and transformation while remaining LLM-friendly.

### IV. Installable via CLI Bootstrap

Reforge MUST be installable via a simple CLI command that copies the framework files into a target project.

**Non-negotiable rules:**
- Installation MUST be achievable via `specify init <project> --template reforge` or equivalent
- Installation MUST NOT require Node.js, Python, or other runtime dependencies for the framework itself
- The installed framework MUST be fully functional with only the AI agent present
- All framework files MUST live under `.reforge/` directory

**Rationale:** Zero-dependency installation ensures immediate usability and eliminates environment setup friction.

### V. Agent-Agnostic Design

Reforge MUST work with any capable AI coding assistant without agent-specific code.

**Non-negotiable rules:**
- Prompt templates MUST NOT reference specific agent names (avoid "Claude MUST..." — use "The agent MUST...")
- Commands MUST use only common tool patterns: file read, file write, glob, grep, directory listing
- Framework MUST NOT depend on agent-specific features (MCP servers, custom tools)
- Documentation MAY include agent-specific tips in clearly marked optional sections

**Rationale:** Agent-agnostic design future-proofs the framework and maximizes adoption across different AI tools.

### VI. Extensibility via Tooling Layer

Additional tooling (validators, transformers, visualizers) MAY be added as an **optional layer** that enhances but never replaces the core LLM workflow.

**Non-negotiable rules:**
- Core workflow MUST function without any optional tooling
- Optional tools MUST be clearly separated in `.reforge/tools/` or external packages
- Tools MUST NOT be required for any slash command to complete
- Tools SHOULD provide value-add capabilities: validation, visualization, export to other formats

**Rationale:** Keeping tooling optional maintains the zero-dependency core while allowing power users to enhance their workflow.

## Project-Specific Context

The file `.reforge/memory/project-context.md` (created via `/reforge.init`) contains
project-specific guidance. When present, treat its contents as supplemental rules
that operate alongside this constitution. The constitution takes precedence on conflicts.

## Command Workflow

### Setup Phase

0. **`/reforge.init`** — Define project context (name, tech stack, domain knowledge, analysis rules)

### Analysis Phase

1. **`/reforge.analyze`** — Scan codebase, identify modules, detect languages, create analysis inventory
2. **`/reforge.extract [type]`** — Extract specific elements (business-rules, database, ui, workflows)
3. **`/reforge.clarify`** — Interactive clarification for ambiguous extractions

### Generation Phase

4. **`/reforge.generate [artifact]`** — Generate documentation from extracted knowledge
5. **`/reforge.status`** — Report on analysis completeness and coverage

### Verification Phase

6. **`/reforge.audit [type]`** — Audit extraction coverage, identify gaps and stale references
7. **`/reforge.fix`** — Execute corrections from the audit correction plan

### Workflow Rules

- Analysis MUST complete before generation
- Each extraction type MAY be run independently
- Clarify MAY be invoked at any point to resolve ambiguities
- All commands MUST be idempotent — running twice produces same result

## Governance

### Amendment Process

1. Proposed changes MUST be documented with rationale
2. Changes affecting core principles (I-VI) require explicit justification
3. All amendments MUST update the version number per semantic versioning:
   - **MAJOR**: Principle removal or incompatible redefinition
   - **MINOR**: New principle, section, or material expansion
   - **PATCH**: Clarifications, typo fixes, non-semantic changes

### Compliance

- All slash commands MUST be validated against this constitution before merge
- The Constitution Check section in plan templates MUST verify principles I-VI
- Violations MUST be documented in Complexity Tracking with explicit justification

### Guidance Files

- `CLAUDE.md` (or equivalent agent file) SHOULD reference this constitution
- Runtime guidance MUST NOT contradict constitutional principles
